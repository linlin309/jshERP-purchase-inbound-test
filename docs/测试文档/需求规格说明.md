# jshERP 采购入库 需求规格说明

> 被测系统：jshERP（管伊佳ERP）3.6-SNAPSHOT ｜ 上游 commit `26f301a9`

## 一、文档说明

jshERP 是开源项目，上游没有产品团队，也没有 PRD 或需求评审记录。本文档描述**采购入库功能应该怎样工作**，作为测试用例设计的输入。

**需求来源**：需求由代码与界面逆向整理得出。整理过程中，从代码里读到若干"实现与合理业务预期不一致"的点，先作为疑点记录，再逐一在界面上构造场景验证，确认可复现后才认定为缺陷。已确认的 8 条差异见附录。

**本文档只覆盖本轮测试范围内的功能**，范围外的功能不在此描述。

**本文档不含**接口定义、表结构、代码实现等细节，只描述业务规则与预期行为。

## 二、背景与范围

### 2.1 系统定位

jshERP 是进销存 + 财务一体的管理系统。核心对象是**单据**，一张单据由两部分组成：

- **表头**：单号、类型、往来单位、日期、金额、状态
- **明细**：商品、数量、单价、仓库、批号/序列号

采购入库是进销存链路的起点：采购的东西入库，库存增加，后续才能销售出库。

### 2.2 本次范围

**范围内**

- 采购入库单的新增、保存、审核、反审核、修改、删除
- 单据对库存的影响
- 界面按钮权限与接口权限
- 配置开关对上述行为的影响

**范围外**

- 采购订单关联与分批入库（含订单状态回写）
- 财务凭证、应付账款
- 多级审批
- 序列号、批号、多单位的完整链路（各保留 1 条针对性验证）
- 商品档案维护
- 性能、安全渗透

## 三、角色与权限

### 3.1 角色

| 角色 | 说明 |
|---|---|
| 系统管理员 | 平台超管，不用于业务测试 |
| 租户用户 | 业务操作者，可被赋予不同角色 |
| 自定义角色 | 由管理员创建，配置菜单权限、按钮权限、数据权限 |

### 3.2 菜单权限

控制用户能看到哪些功能页面。未授权的菜单不显示，直接访问也不应成功。

### 3.3 按钮权限

控制页面里哪些操作按钮可见。编号含义：

| 编号 | 权限名 | 在采购入库页面控制的按钮 |
|---|---|---|
| 1 | 编辑 | 新增、删除、转采购退货、强制结单、修正欠款 |
| 2 | 审核 | 审核 |
| 3 | 导出 | 导出 |
| 4 | 启用禁用 | — |
| 5 | 打印 | — |
| 6 | 作废 | — |
| 7 | 反审核 | 反审核 |

- 勾选某编号，对应按钮才显示
- **编号 1 名为「编辑」，实际控制 5 个按钮**，取消后新增和删除一起消失

### 3.4 数据权限

角色的数据类型有三档：

| 类型 | 可见范围 |
|---|---|
| 全部数据 | 本租户所有单据 |
| 本部门数据 | 本部门成员创建的单据 |
| 个人数据 | 仅自己创建的单据 |

### 3.5 权限的生效边界

- 菜单和按钮权限控制**界面可见性**
- **权限必须在服务端生效**：没有权限的用户即使绕过界面，也不应能完成对应操作

## 四、单据类型与生命周期

### 4.1 单据类型

单据由两个维度共同定义：

- **大类**：入库 / 出库 / 其它
- **子类**：采购 / 销售 / 采购退货 / 销售退货 / 采购订单 / 调拨 / 组装单 / 拆卸单 / 盘点复盘 等

**采购入库 = 大类「入库」+ 子类「采购」。**

> 注意：**采购订单**属于大类「其它」，不是「入库」。两者是不同的单据。

### 4.2 状态定义

| 值 | 含义 | 界面显示 |
|---|---|---|
| 0 | 未审核 | 红色「未审核」 |
| 1 | 已审核 | 绿色「已审核」 |

**采购入库单只会在 0 和 1 之间流转。**

### 4.3 允许的状态迁移

| 动作 | 前置条件 | 结果 | 不满足时 |
|---|---|---|---|
| 审核 | 当前为「未审核」 | 变为「已审核」 | 拒绝，提示只有未审核的单据才能审核 |
| 反审核 | 当前为「已审核」 | 变为「未审核」 | 拒绝，提示只有已审核的单据才能反审核 |
| 删除 | 当前为「未审核」 | 单据不再显示 | 拒绝，提示只有未审核的单据才能删除 |
| 修改 | 当前为「未审核」 | 内容更新 | 拒绝，提示当前状态下不能修改 |

## 五、业务流程

### 5.1 建单

- 进入「采购入库 → 新增」
- 系统自动生成单据编号并填入
- 单据日期默认当天
- 结算账户默认带出默认账户
- 明细区默认一行空行

**预期**：

- 打开页面即占用一个单据编号；不保存直接关闭会跳号，属正常现象
- 单据编号可手工修改

### 5.2 保存

**预期**：

- 表头和明细一起保存，任一项校验不通过则整单不保存
- 保存后状态为「未审核」
- 保存后单据出现在列表中
- 保存后库存按最新数据重算，是否计入取决于「强审核」开关（见 7.1）

### 5.3 审核

**预期**：

- 只有「未审核」的单据能审核
- 审核后可执行的操作减少：不能再修改、不能直接删除
- 审核是否影响库存，取决于「强审核」开关（见 7.1）

### 5.4 反审核

**预期**：

- 只有「已审核」的单据能反审核
- 反审核后回到「未审核」，可再次修改或删除

### 5.5 修改

**预期**：

- 只有「未审核」的单据能修改
- 修改后明细整体更新
- 修改后库存按新内容重算

### 5.6 删除

**预期**：

- 只有「未审核」的单据能删除
- 删除后单据不在列表显示
- 删除后库存按剩余单据重算
- 被财务单据关联的单据不能删除
- 序列号已出库的入库单不能删除
- 删除入库单时，其序列号一并释放

## 六、业务规则

### 6.1 表头字段

| 字段 | 规则 | 预期 |
|---|---|---|
| 单据编号 | 必填，全局唯一，最长 50 字符 | 为空或重复时拒绝保存 |
| 单据日期 | **必填** | 为空时拒绝保存 |
| 供应商 | **必选** | 未选时拒绝保存 |
| 结算账户 | 采购、采购退货、销售、销售退货四类单据**必选** | 未选时拒绝保存 |
| 本次付款 | 必填，可填 0；必须是数字，最多 4 位小数 | 为空或格式错误时拒绝保存 |
| 优惠率 | 选填，百分比（系统按「优惠率 ÷ 100」折算优惠金额）；应限定 0–100 | 超出范围时应提示 |
| 备注 | 选填，最长 1000 字符 | 超长时拒绝并提示 |
| 附件 | 选填，**最多 4 份** | 超过时拒绝并提示 |

### 6.2 明细字段

| 字段 | 规则 | 预期 |
|---|---|---|
| 仓库 | **必选**（采购入库必须有仓库） | 未选时拒绝保存 |
| 商品条码 | **必选**，且必须是商品档案里存在的商品 | 不存在时拒绝保存 |
| 数量 | **必填，必须大于 0**；最多 6 位小数 | 为空、为 0、为负、超精度时拒绝并提示 |
| 单价 | 选填，最多 6 位小数 | 格式错误时拒绝 |
| 金额 | 由系统按「数量 × 单价」得出 | 应与数量×单价一致 |
| 税率 / 税额 / 价税合计 | 选填，系统按税率计算 | — |
| 批号 | 商品启用了批号时**必填**，最长 100 字符 | 为空时拒绝保存 |
| 序列号 | 商品启用了序列号时**必填**，且**个数必须等于数量**；单个最长 64 字符 | 数量不符或重复时拒绝保存 |
| 明细备注 | 选填，最长 500 字符 | 超长时拒绝并提示 |

**明细行数**：至少 1 行。没有明细的单据不能保存。

### 6.3 保存时的校验

按以下顺序校验，任一不通过则整单不保存：

1. 单据编号是否重复
2. 结算账户是否为空（限四类单据）
3. 多账户场景下，各账户金额合计是否等于本次付款
4. 附件是否超过 4 份
5. 明细是否为空
6. 每行明细的商品、仓库、数量、序列号、批号是否合规

### 6.4 库存规则

#### 6.4.1 库存什么时候变

| 动作 | 库存是否变化 |
|---|---|
| 保存单据 | 是，按最新数据重算（是否计入取决于「强审核」开关，见 7.1） |
| 修改单据 | 是，按新内容重算 |
| 删除单据 | 是，按剩余单据重算 |
| 审核 / 反审核 | 仅当「强审核」开启时影响库存，见 7.1 |

#### 6.4.2 库存怎么算

```
当前库存 = 初始库存 + 盘点调整 + 入库合计 − 出库合计
```

- 全部按**基础数量**计算，不是录入数量
- 多单位商品（如 1 箱 = 12 个）录入「1 箱」时，按 12 计入

#### 6.4.3 库存不足校验

**采购入库是入库方向，不参与库存不足校验**——入库只会增加库存。

### 6.5 单据编号

| 规则 | 预期 |
|---|---|
| 生成时机 | 打开「新增」页面时生成并占用 |
| 格式 | 前缀（采购入库为 `CGRK`）+ 流水号 |
| 唯一性 | 全局唯一，重复时拒绝保存 |
| 可修改 | 用户可以手工改，改后仍需唯一 |
| 跳号 | 打开页面不保存会消耗一个号，属正常现象 |

### 6.6 金额与符号

- 明细金额为正数
- 采购入库的表头「合计金额」和「本次付款」以**负数**存储和展示
- 本次付款可小于合计金额（形成欠款），也可等于

## 七、配置开关的影响

### 7.1 强审核

配置是**租户级**的，切换会影响该租户所有后续操作。

| 开关 | 保存后库存 | 审核/反审核 | 审核时库存不足校验 |
|---|---|---|---|
| 关闭 | 立即计入 | 不影响库存 | 不触发 |
| **开启** | 不计入（只有已审核的才算） | **审核后计入，反审核后扣除** | 具备触发条件 |

## 八、异常场景与提示

以下为业务层面应被拦截的场景，以及用户应看到的提示。

| 场景 | 应提示 |
|---|---|
| 单据编号重复 | 单据编号已经存在 |
| 单据日期为空 | 请输入单据日期 |
| 未选供应商 | 请选择供应商 |
| 未选结算账户 | 结算账户不能为空 |
| 本次付款为空 | 请输入金额，如果为空请填0 |
| 本次付款格式错误 | 金额格式不正确 |
| 单据无明细 | 单据明细不能为空 |
| 明细未选仓库 | 仓库不能为空 |
| 明细商品不存在 | 商品在商品管理中不存在 |
| 数量为空 / 为 0 / 为负 | 数量必须大于 0 |
| 数量超出精度 | 数量最多支持 6 位小数 |
| 序列号个数与数量不符 | 商品条码 XXX 的数量与序列号不一致 |
| 序列号商品未填序列号 | 商品条码 XXX 的序列号不能为空 |
| 批号商品未填批号 | 商品条码 XXX 的批号不能为空 |
| 同一单据内序列号重复 | 单据明细中存在重复的序列号 |
| 附件超过 4 份 | 单据附件不能超过 4 份 |
| 备注超长 | 备注长度不能超过 1000 个字符 |
| 审核已审核的单据 | 只有未审核的单据才能审核 |
| 反审核未审核的单据 | 只有已审核的单据才能反审核 |
| 删除已审核的单据 | 只有未审核的单据才能删除，请先进行反审核 |
| 修改已审核的单据 | 单据当前状态下不能修改 |
| 删除被财务单据关联的单据 | 单据被财务单据关联，不允许单独删除 |
| 删除序列号已出库的入库单 | 单据的序列号已经出库，不能删除 |
| 短时间重复提交同一单号 | 请不要频繁提交单据 |

> 任何异常都应返回**可读的业务提示**，不应出现「未知异常」「系统错误」或堆栈信息。
>
> 表中「数量」相关的三条提示为**应然要求**——当前系统对数量没有值校验，这几条提示尚不存在，对应附录的 D-02 / D-03。

## 附录：需求与实现的已知差异

整理需求时，从代码里读到以下 8 处"实现与本文档规则不一致"的点。每一处都在界面上构造场景验证过，确认可复现后才列入。

详细复现步骤、证据与修复建议见飞书缺陷库：
<https://zwy-linlin.feishu.cn/base/M3U3bt1Hfad2eFsWRT3cAfrrn0e?table=tbl3OefR9cRAgm51&view=vew3TPKmsz>

级别口径：`致命` > `严重` > `一般` > `轻微`。8 条中 D-09 为致命级（金额可被任意篡改落库），其余为严重及以下。

| 编号 | 缺陷 | 严重程度 | 关联正文 |
|---|---|---|---|
| D-01 | 服务端不校验按钮权限，绕过界面可直接审核单据 | 严重 | 3.5 |
| D-02 | 数量可录入负数并保存成功 | 严重 | 6.2 |
| D-03 | 数量可录入 0 并保存成功 | 一般 | 6.2 |
| D-04 | 数量超出 6 位小数时静默舍入，无提示 | 轻微 | 6.2 |
| D-06 | 服务端不校验必填字段（单据日期/供应商/数量），绕过界面可存出脏数据 | 严重 | 6.1、6.2 |
| D-07 | 本次付款为空时触发空指针，返回「未知异常」 | 一般 | 6.1、八 |
| D-08 | 备注超长未校验，返回「未知异常」 | 轻微 | 6.1、八 |
| D-09 | 明细金额与数量×单价不一致时不校验 | 致命 | 6.2 |

**共性**：D-01 和 D-06 属于同一类问题——**界面做了控制，服务端没做**。凡是依赖前端拦截的规则，都需要单独验证服务端是否也拦得住。

其余 14 条（D-05、D-10～D-22）见缺陷记录表；D-05 属商品信息页，不在本轮采购入库范围。
