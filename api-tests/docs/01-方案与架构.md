# 01 - 接口自动化方案与架构

> 状态：M1 草案（2026-11-09）
>
> 输入：[需求规格说明](../../docs/测试文档/需求规格说明.md)、[43 条手工用例](../../docs/测试文档/04-测试用例.md)、实际接口验证
>
> 对应代码：[api-tests](../README.md)

## 一、目标

用 pytest + requests 覆盖采购入库主链路的接口层判定，和手工测试互补，而不是把 43 条手工用例逐条翻译成脚本。

成功标准：

1. 34 条接口用例可以独立执行，失败时能看到接口、HTTP 状态、业务码和响应体（34 条为初始规划口径，实际用例清单见 [04-接口测试用例](04-接口测试用例.md)）。
2. 采购入库主链路（创建 → 审核 → 反审核 → 编辑 → 删除）可以重复执行，结果不依赖前端页面。
3. 用例与需求、手工用例之间可追溯；接口结论不混入本轮手工测试结论。
4. 测试数据可识别、可清理；不直接改库，不留下无法解释的库存差异。
5. 默认执行不要求前端 3000 启动；后端 9999、MySQL、Redis 可用即可。

本阶段（M1）只交付方案文档 01-03 和只读 smoke，不写业务数据、不做数据库断言、不做配置与权限用例。

### 2.1 接口范围

共 21 个接口/接口组，分两层：

| 层 | 内容 | 数量 |
|---|---|---|
| 主链路 | 登录、供应商/仓库/账户/商品基础资料、单据新增/列表/详情/编辑/审核/删除、库存查询 | 12 |
| 断言与扩展 | 会话、单据主表/明细、批量删除、进销存、序列号、关联单据、系统配置 | 9 |

完整清单、方法、参数与响应要点见 [02-接口清单](02-接口清单.md)。

| S 状态机 | 保存/审核/反审核/编辑/删除的合法与非法流转 | 6 |

### 2.3 手工 43 条的适配

| 判定层 | 数量 | 处理 |
|---|---|---|
| API 可独立判定 | 32 | 转成接口用例，接口结果作为主证据 |
| 混合 | 8 | 接口造数/断言 + 页面观察；仍按手工用例执行 |
| UI | 3 | 保留手工，接口自动化不覆盖 |

接口用例是重新设计，不是逐条翻译：手工用例里的页面步骤、截图和交互观察不会原样搬进脚本；接口用例只保留服务端可判定的业务规则。

### 2.4 非目标

- 不做 UI 自动化，不替代页面渲染、按钮显隐、交互提示的检查。
- 不覆盖附件上传、导出、打印、财务凭证完整链路、多级审批。
- 不做性能、压力、安全渗透、并发。
- 不修改 jshERP 产品代码；发现的问题只记录，不修复。
- 不在本阶段做 CI、并行执行、Allure。

## 三、测试策略

### 3.1 分层判定

| 层 | 适合判定 | 例子 |
|---|---|---|
| API | 服务端规则、字段契约、状态流转、权限拦截、异常返回 | 数量为 0 是否拒绝、审核后能否编辑、无权限能否调接口 |
| 混合 | 接口造数/断言，页面观察最终表现 | 默认值、按钮显隐、页面提示 |
| UI | 纯前端渲染与交互 | 布局、文案、控件状态 |

### 3.2 为什么不是“把手工用例翻译成脚本”

手工用例的预期往往包含页面状态和人工观察；接口用例的预期必须是可编程断言的 HTTP/JSON/数据库结果。两者共用业务规则，但断言对象不同。强行一一对应会产生大量脆弱脚本，所以本轮按“服务端可判定”重新拆分。

### 3.3 与手工测试的关系

- 业务预期仍以 [需求规格说明](../../docs/测试文档/需求规格说明.md) 为准；接口用例不另造需求。
- 手工 43 条用例仍是完整业务覆盖的正本；接口 34 条只覆盖服务端可判定部分（初始规划口径，实际清单见 04 文档）。
- 接口失败先分三类：产品缺陷、测试数据/配置问题、接口契约理解错误；按测试计划的缺陷判定原则处理，不直接把接口失败当产品缺陷。

## 四、技术栈与选型

| 组件 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.12.10 | 本机已装；requests/pytest 生态成熟 |
| 测试框架 | pytest 8.x（venv 内） | fixture、marker、参数化、报告插件齐全 |
| HTTP | requests 2.32.x | 直接、稳定，便于看请求/响应 |
| 配置 | python-dotenv | `.env` 与代码分离，避免账号进仓库 |
| 报告 | pytest-html | 单文件 HTML，足够个人项目 |
| 数据库断言 | PyMySQL（仅 M4 引入） | 只读查询库存/单据；不参与造数 |
| 隔离 | venv | 与全局 pytest 9.x 隔离，版本可复现 |

暂不引入：

- Apifox / Postman 作为自动化工具：可用于手工探查接口，但脚本化、版本管理、CI 不如 pytest。
- Allure：pytest-html 已能满足本轮报告需求。
- pytest-xdist：配置类用例必须串行，首轮不做并行，避免库存/配置互相污染。

## 五、工具链

- 编辑器：VS Code（本机已安装，`code` 在 PATH）；Trae/Cursor 可选，不是必需。
- 版本管理：Git；测试代码与文档同仓库。
- 运行：PowerShell 7（`pwsh.exe`）或 Git Bash；项目内使用 venv。
- 标记：`smoke` / `write` / `config` / `permission`。
- 报告：`pytest --html=reports/report.html --self-contained-html`。
- 数据库核对：M4 起用只读 SQL；本阶段不需要数据库客户端。

## 六、总体架构

```text
tests/test_*.py
        │
        ▼
conftest.py  ── session 级 client、后续数据 fixture
        │
        ▼
client.py    ── ErpClient：login / get / post / put / delete
        │
        ├── config.py  ── .env → Settings
        ▼
jshERP API（http://localhost:9999/jshERP-boot）
        │
        ▼
MySQL 3307 / Redis 6379
        └── M4 只读断言，不在测试里写库
```

约定：

- 测试只通过 `ErpClient` 发请求，不直接在用例里写 `requests.*`。
- 登录只在 session fixture 做一次；所有用例复用同一个 token。
- 造数与清理放在 fixture 或用例的 `try/finally`；M1 不造数。
- 数据库断言只读；不直接改 `delete_flag`、业务日期或库存。

## 七、环境基线

| 项 | 值 | 说明 |
|---|---|---|
| 后端 | `http://localhost:9999/jshERP-boot` | Spring Boot；M1 smoke 依赖 |
| MySQL | `127.0.0.1:3307` | 库 `jsh_erp`；M4 只读断言 |
| Redis | `127.0.0.1:6379` | 会话/验证码 |
| 租户 | 63 | 演示租户 |
| 验证码 | `checkcode_flag=0` | 登录可传空 `code`/`uuid`；开启后 M1 不适用 |
| 强审核 | `force_approval_flag` | 手工轮次基线为开启（1）；接口自动化执行前读取并记录，不写死 |
| 登录密码 | 前端发送 `md5(明文)` | 后端直接比较；`.env` 存明文，客户端负责 MD5 |
| 上游版本 | commit `26f301a9` | 与手工测试一致 |

配置类用例（M4）必须：先读当前值 → 记录 → 修改 → 执行 → `finally` 恢复；默认不跑，需显式开启。

## 九、风险与限制

| 风险 | 影响 | 应对 |
|---|---|---|
| 后端未启动 | smoke 直接失败 | conftest 捕获连接错误，提示先启动 9999 |
| 登录密码/验证码/账号不一致 | 所有用例阻塞 | `.env` 存明文；client 做 MD5；确认 `checkcode_flag=0` |
| 业务错误形态不统一 | 断言漏判 | 已见 `code=200` + `data.msgTip`；M2 统一 `assert_business_error`，同时看 HTTP 状态 |
| 配置开关全局生效 | 库存类结论互相污染 | 配置用例串行、opt-in、读前快照、finally 恢复 |
| 删除受限/清理失败 | 残留单据影响库存 | `API-` 前缀可识别；清理失败记录单号并告警，不直接改库 |
| 权限用户缺失 | P 组无法执行 | M5 准备受限用户；在此之前标记跳过 |
| 响应字段未完全实测 | 文档与实现漂移 | 02 逐项标“已验证/待 M2”；M2 用真实响应校准 |
| 演示数据 ID 变化 | 用例脆弱 | 示例 ID 只用于文档；M2 从基础资料接口动态取 |
| 单人项目无 CI | 回归靠本地 | M1 先保证本地可重复；CI 后续再加 |
